# Full Futures historical replay

## Retention checkpoint — 2026-10-18

The older frozen Futures input workspace was deliberately removed during
user-approved cleanup. Redirected `retired_metadata` links contain reports only;
they are not replay inputs. The replay CODE remains available, but a new Futures
experiment must freeze new inputs. Current retained Spot data/results are indexed
at `~/research_snapshots/SPOT_RESEARCH_RESULTS.md`.

This extends the signal lab, using the **pinned production
DirectionalFuturesSimulationService.run()**, not a second implementation of
trading rules. Existing legacy 5m replay commands remain unchanged.

## What is replayed

- Indicator/context reconstruction and six-component/master signal calculation.
- Regenerated market plans, entry location, timing, zone and account permissions.
- Margin allocation, available capital, exposure, position slots and cooldown.
- Structure-aware execution setup and freshly calculated TP/SL levels.
- Open positions, 1m candle exit resolution, LONG profit-lock and fees.
- Production accounting, realized/unrealized PnL, equity and generated events.

Weights, thresholds, permission rules, sizing, fees and exit formulas are frozen.
A candidate changes one declared component; levels, positions and later account
decisions are free to change **as consequences**. Positions are not copied from
the old run or forcibly matched to its trades.

## Initialization and chronological inputs

Use a `signal-lab-create` workspace with separate Trading/Market SQLite backups,
pinned Python source, hashes and a fixed UTC period. No live files are modified.
The first captured resolved engine state initializes the account once, including
inherited positions, prior accounting and signal history for entry timing.
Every subsequent cycle evolves that account. No later historical state is
injected. Inherited counts are separated from `stats_delta` for the replay period.

The recorded cycle schedule includes complete ON_TIME and LATE first decisions.
Unlike the signal-quality screen, a late cycle cannot be discarded silently:
it could have changed the account. Incomplete evidence aborts a portfolio run.
No missing cycles are invented or filled from a current database.

Market context is reconstructed from hash-checked captured candle revisions.
Exit monitoring uses the full captured 1m history, not an indicator warmup tail,
so positions inherited before the selected period can resolve correctly.
Permission indicators are retained as the captured point-in-time series; market
plans are regenerated by pinned code. This version supports component/MTF
changes, not edits to the historical indicator pipeline or market-plan rules.

## Two execution modes, deliberately separate

1. **Observed** baseline: use recorded ticker quotes and original decision times.
   Compare signals, permission checks, entry quality and location/zone decisions
   exactly. Compare evolving state against the next captured pre-cycle state.
   This validates reconstruction, not a candidate's profitability.
2. **Next-minute** baseline/candidate: use the exact next 1m candle open strictly
   after recorded evidence/decision/quote availability. Both variants use the
   same declared model. A recorded NO_SIGNAL often has no ticker quote; do not
   fabricate an "observed" quote for its counterfactual trade. Missing model
   candles deny the entry and are reported, without interpolation.

The model's candle must be complete before the frozen end boundary. Only its
open is used as the execution price, not its high/low/close. This is an execution
assumption, not evidence of a real historical fill. Position exits still follow
the production pre-entry lifecycle/cycle schedule with candles available at the
original cycle, not newly available bars introduced by a modeled execution delay.

## Commands

```bash
cd /home/sandro/SmartSignalHub
export LD_LIBRARY_PATH=/home/sandro/research_snapshots/readiness_R21_20260927/sqlite
# 1. Historical reproduction, including independent terminal/event verification.
venv/bin/python -m platform_v2.tools.research portfolio-lab-run WORKSPACE
venv/bin/python -m platform_v2.tools.research portfolio-lab-verify WORKSPACE
# 2. Uniform execution-model baseline (requires verified observed baseline).
venv/bin/python -m platform_v2.tools.research portfolio-lab-run WORKSPACE \
  --execution-model next-minute
# 3. Editable offline candidate; edit only the declared component's code.
venv/bin/python -m platform_v2.tools.research signal-lab-candidate WORKSPACE mtf_trial_01
venv/bin/python -m platform_v2.tools.research portfolio-lab-run WORKSPACE \
  --execution-model next-minute --name mtf_trial_01 --component mtf
venv/bin/python -m platform_v2.tools.research portfolio-lab-compare WORKSPACE mtf_trial_01
```

`WORKSPACE` is an absolute path, e.g.
`/home/sandro/runtime_archives/trading_epoch_2026-10-18_v1/retired_metadata/research_snapshots_2026-10-18/futures_signal_lab_20261011`.

Runs are retained in `portfolio_runs/`, separate from signal-only `runs/`.
Each run preserves worker/adapters, exact candidate source, execution protocol,
`result.json`, `portfolio.json`, `replay.sqlite3` and a hash manifest. The database
contains private rows, metrics and initial/final state. Run destinations cannot
be overwritten. `--limit N` is a smoke test, not full historical verification;
use a new workspace for another limit/period or preserve an old run elsewhere.

The observed verifier checks all replay OPENED/CLOSED events against frozen
archive rows (timestamps, prices, fees, PnL, management) and checks the final
account against the archive's terminal state. Terminal verification therefore
requires the replay period to reach the archive's last recorded cycle; a shorter
period cannot be called terminal-parity verified by this command.

## Comparison and acceptance

First run the **unchanged** candidate and require zero changed signals,
permissions and final state. Then evaluate a declared component change. Other
component scores changing on the same cohort aborts the run; this is an observed
cohort guard, not a proof of isolation on unseen inputs.

The full comparison shows changed signals/permissions, period trade/close/PnL
deltas, denial counts, fees, available/reserved balances, equity and open positions.
Final metrics retain inherited production accounting; use period deltas and
equity changes, not cumulative lifetime PnL as candidate-period profit. Fee
recognition follows production accounting, not a newly invented cash-flow model.

Failure to reproduce the historical baseline blocks modeled/candidate runs.
Changed input/source/run hashes block comparisons. The worker denies network,
process spawning, live-runtime access and filesystem mutation outside its run.
Only private output SQLite is writable. These are side-effect guards, not a
security sandbox for hostile code. No service restart, alert or deployment occurs.

## Remaining limitations

- Captured cycle replay, not uninterrupted tick-by-tick trading.
- Existing conservative stop-first ordering when both SL/TP touch in one 1m
  candle; actual intrabar sequence and exchange fills are unknown.
- Production fee model retained; no additional funding, spread, slippage or
  exchange microstructure model is introduced. Next-minute prices are assumed.
- Open positions stay open at sample end; no artificial end-of-period close.
- Recorded repeated/retry cycles outside the first-decision schedule are not
  invented. Any effect is expected to fail state/event parity, not be hidden.
- The initial verified period is September 28–October 10, 2026. Older history is
  preserved as needed for inherited state/warmup, not claimed fully replayable
  under this point-in-time evidence protocol. The sealed earlier holdout is not
  evaluated for strategy selection.
- Reused exploratory history, not independent validation or automatic promotion.
